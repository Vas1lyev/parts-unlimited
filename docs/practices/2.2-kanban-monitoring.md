# Практическая работа 2.2 — Канбан, мониторинг и командный процесс

## Результат

В GitHub Project настроены статусы, WIP-лимит, приоритеты, теги,
представления и диаграмма по исполнителям.

## Настройка канбан-доски

Добавлен статус `Утверждено QA`. В его описании зафиксированы:

- лимит незавершённой работы: `WIP = 1`;
- определение готовности: «проходят все тесты».

История «Как клиент, я хочу запрашивать новые учебные материалы» перенесена на
этап `Утверждено QA`. История о недавно просмотренных материалах оставлена на
этапе `Разработка завершена`.

Для карточек созданы поля:

- `Тег` со значениями `данные` и `ux`;
- `Дополнительный тег` для одновременной фиксации второго признака;
- `Приоритет` со значениями `Обычный` и `Ускоренный`;
- `Лимит WIP`.

Истории о просмотре новых материалов присвоены признаки `данные` и `ux`.
Истории о недавно просмотренных материалах присвоен приоритет `Ускоренный`.
Создано отдельное представление `Ускоренная`.
Значение `данные` выделено жёлтым цветом, а деятельность `Разработка` — зелёным.

## Мониторинг

Создано представление `Веб-задачи`, которое выбирает элементы типа `Задача` из
области `PUL-Web` и группирует их по исполнителю. В GitHub Insights создана
диаграмма `Веб-задачи — по назначению`, показывающая количество задач каждого
исполнителя.

Для контроля работ используются представления `Итерация 2`, `PUL-Web`,
`По исполнителям` и `Веб-задачи`.

## Настройка процесса

Создано текстовое поле `PUL Ticket ID`. Для пользовательской истории о просмотре
новых материалов установлено значение `PUL-TRAINING-001`. Поле доступно для
фильтрации и отчётности внутри GitHub Project.
