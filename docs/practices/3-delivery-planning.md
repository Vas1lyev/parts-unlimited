# Практическая работа 3 — Управление календарём и планом поставки

## Результат

В GitHub Project настроено представление Roadmap `Поставка веб-приложения`.
Оно показывает элементы двух команд и исключает статус `Готово` фильтром
`-status:Готово`.

## Календарь и маркер

Для плана создана веха `Команда в отпуске` с датой 27 ноября 2026 года — это
последняя пятница текущего месяца на момент выполнения работы.

В проект добавлены поля `Начало` и `Срок`, позволяющие отображать на одном
Roadmap независимые и не совпадающие по ритму графики команд.

## Внешняя команда и итерации

Для работ с внешними сервисами используется команда `External integrations`.
Создано итерационное поле `График поставки` со следующими интервалами:

| Итерация | Начало | Окончание | Назначение |
| --- | --- | --- | --- |
| Итерация 50 | 24.11.2026 | 11.12.2026 | Приоритетная интеграция данных доставок |
| Итерация 51 | 14.12.2026 | 01.01.2027 | Интеграция с метеорологической службой |
| Спринт 4 | 03.01.2027 | 16.01.2027 | Функция отслеживания доставки команды PUL-Web |

Итерация 50 начинается в день выполнения работы и заканчивается в третью
пятницу. Итерация 51 начинается в следующий понедельник и заканчивается в третью
пятницу после начала. Команда `PUL-Web` работает по двухнедельным спринтам.

## Решение зависимости

В план добавлены рабочие элементы:

- [Интеграция с метеорологической службой](https://github.com/Vas1lyev/parts-unlimited/issues/8);
- [Интеграция с корпоративными данными доставок](https://github.com/Vas1lyev/parts-unlimited/issues/9);
- [Как клиент, я хочу отслеживать данные доставки](https://github.com/Vas1lyev/parts-unlimited/issues/10).

Интеграция с корпоративными данными доставок назначена на `Итерацию 50`,
интеграция с метеорологической службой — на `Итерацию 51`. Пользовательская
история команды `PUL-Web` назначена на `Спринт 4`.
