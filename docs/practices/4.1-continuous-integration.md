# Практическая работа 4.1 — Непрерывная интеграция

## Результат

Для приложения Parts Unlimited настроен workflow `Parts Unlimited CI`. Он
выполняется на GitHub-hosted runner `windows-2022` и запускается автоматически
при изменениях приложения или файла workflow в ветке `main`.

## Сборочный конвейер

Workflow `.github/workflows/parts-unlimited-ci.yml` выполняет следующие шаги:

1. получает исходный код репозитория;
2. подключает MSBuild;
3. устанавливает reference assemblies .NET Framework 4.5.1 и 4.5.2;
4. восстанавливает пакеты NuGet;
5. собирает и публикует ASP.NET-приложение;
6. собирает и запускает модульные тесты;
7. загружает собранный сайт как артефакт `parts-unlimited-website`.

Конвейер также можно запустить вручную через `workflow_dispatch`. Для pull
request в ветку `main` выполняется такая же проверка сборки и тестов.

## Проверка непрерывной интеграции

Первый полный запуск успешно собрал приложение, выполнил модульные тесты и
загрузил артефакт.

После этого в файле
`PartsUnlimited-aspnet45/src/PartsUnlimitedWebsite/Views/Home/Index.cshtml`
заголовок `Arrivals` изменён на `New Arrivals`. Коммит с изменением автоматически
запустил workflow. Повторный запуск также завершился успешно.
